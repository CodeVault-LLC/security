## Design Specificity Verdict

The core workspace feels authored for vulnerability researchers. Report audience, TLP, evidence visibility, approvals, prior-art conclusions, digests, disclosure state, and audit language create real product character. The missing layer is the Alpha 7 evaluator experience: the clean start still feels like an internal deployment requiring maintainer knowledge.

The deterministic scan examined 69 desktop source files and emitted 18 warnings. Five side-tab, ten font-overuse, two broken-image, and one aphoristic-copy warning were either generated-code hits or false positives. The two source broken-image hits came from Mermaid-related string matching, not rendered broken images. It found no reliable source-level design defect. The absence of connection preflight, onboarding, evaluator guidance, branding fields, and rendered version information was confirmed from source and live behavior.

No reliable detector overlay was available in the shared browser because the browser page had no Electron preload bridge. Native Electron automation supplied the rendered evidence instead.

## Overall Impression

The product underneath Alpha 7 is more mature than the milestone experience around it. The automated core is unusually healthy and the research workspace is credible, but a new evaluator cannot discover, start, or complete the promised sample-report journey without maintainer setup. The single biggest opportunity is to package the existing depth into one disposable, guided, export-ready evaluation path.

## What's Working

- The report workspace communicates security-review semantics well: audience, TLP, lint, approval gates, evidence visibility, digest, and immutable revision concepts are visible without becoming decorative dashboard noise.
- Input handling was resilient. Long validation failures preserved entered data, and Arabic, Hebrew, emoji, path-like text, and script tags rendered as inert text.
- The engineering baseline is strong: formatting, lint, type checking, build, 751 unit/DOM tests, 170 PostgreSQL integration tests, and four end-to-end tests passed.

## Priority Issues

### [P0] The Alpha 7 evaluator path does not exist

**Why it matters:** A clean launch asks for server URL, organization credentials, and MFA. There is no disposable bundle, compatibility preflight, first-run checklist, guided sample, report branding, visible exact build identity, or evaluation/removal guide. The milestone exit criterion cannot currently be attempted by a non-contributor.

**Fix:** Ship one tagged evaluation bundle with fixed local credentials, synthetic data, local object storage and workers, a pre-sign-in health check, and a five-step checklist that deep-links into an export-ready sample case.

**Suggested command:** `$impeccable onboard`

### [P1] Evidence upload failure is not recoverable

**Why it matters:** In a two-file upload, one artifact reached `STORED`, the second failed, no evidence record was created, and retrying without reselecting sent no requests because selection IDs had already been consumed. Picking again retained stale `done` progress by filename. The UI promises that files remain, but they are no longer usable.

**Fix:** Make the upload plus evidence attachment transactional from the user's perspective. Keep file handles valid until completion or explicit cancellation, support per-file retry, clear progress when selections change, key progress by selection ID, and clean up unattached canonical artifacts.

**Suggested command:** `$impeccable harden`

### [P1] Background job state is stale and misleading

**Why it matters:** Prior-art initially showed an empty-result message while the check was queued. The worker completed, but the UI remained queued until the user navigated away and back. A process-local event publisher cannot reliably invalidate a renderer when the worker runs separately.

**Fix:** Poll queued/running prior-art checks as the report export screen already does, or use a durable cross-process event path. Never render the completed empty state before completion.

**Suggested command:** `$impeccable clarify`

### [P1] Report actions and summaries contradict report truth

**Why it matters:** A report with ten blocking issues still presents Export PDF as the primary enabled action and only rejects it after the click. The global Reports list showed `0/0 approved` for reports whose detail views contained 13–20 sections, and loaded reports with one request per case.

**Fix:** Disable approval/export while known blockers exist, explain what must be resolved next to the action, correct summary aggregation, and add an organization-level paginated reports endpoint.

**Suggested command:** `$impeccable optimize`

### [P1] The report workspace breaks under accessibility zoom

**Why it matters:** At a 1024×640 window and 200% zoom, navigation became giant icons, the report reference split, the title and controls clipped, and primary actions moved off-screen without a useful alternate layout. This blocks task completion for low-vision users.

**Fix:** Introduce responsive report-header states, allow actions to wrap into an overflow menu, preserve a usable content column, and test the complete workflow at 200% zoom with keyboard-only navigation.

**Suggested command:** `$impeccable adapt`

## Persona Red Flags

**Jordan, first-time evaluator:** Jordan stops at the server, credential, and MFA screen because there is no test environment or explanation of where credentials come from. If a maintainer gets Jordan through login, the Home screen offers operational alerts instead of a sample-case action. The seeded case creates a report with ten blockers, so the promised first export ends in rejection.

**Alex, working researcher:** Alex trusts the evidence dialog's claim that selections remain after failure, clicks retry, and gets the same generic error without network activity. Reselecting a file can still display stale success. This undermines confidence in evidence custody.

**Riley, low-vision security lead:** Riley can read the normal desktop UI, but 200% zoom makes the report header and actions unreachable. The dense sidebar collapses without replacing navigation with a task-complete compact pattern.

## Minor Observations

- New evidence defaults to Screenshot even for Markdown and JSON; infer a kind when safe or require a deliberate mixed-file choice.
- A 500-character case title reaches the server and returns `body/title must NOT have more than 200 characters`. Add `maxLength`, a counter, and product-language validation.
- The Cases view becomes hard to scan with dozens of cases because it lacks visible status, owner, or date filters.
- The app exposes an `app.version()` bridge but does not render it. Organization settings currently model only name and avatar, so the roadmap's contact and branding data has nowhere to live.
- README still states that alpha packages are unsigned, and the existing verified desktop inventory is Alpha 6.
- The feature register still assigns several unrelated items to Alpha 7, while the roadmap now places the milestone around evaluation. One status source should win.

## Questions to Consider

- Should the sample case demonstrate the complete product, or the shortest credible proof of report projection?
- What is the minimum trustworthy evaluator identity block: version, publisher, build digest, server compatibility, and local-only data status?
- When one file in a batch fails, should CodeVault roll back the whole batch or preserve successful files as an explicit draft awaiting user confirmation?
